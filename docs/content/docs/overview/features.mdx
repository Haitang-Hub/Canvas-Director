# Features

## Canvas projects

- Create, rename, duplicate, delete, import, and export canvas projects.
- Persist projects in the browser and optionally synchronize them with WebDAV.
- Keep viewport, background, nodes, connections, and assistant sessions with each project.

## Infinite canvas

- Pan, zoom, reset the view, select multiple nodes, copy and paste, undo and redo.
- Drag files onto the canvas and use lines, dots, or a blank background.
- Export the entire canvas or selected elements with their resources.

## Nodes and workflows

- Text, image, video, and generation-configuration nodes.
- Connect text prompts and reference media to generation nodes.
- Generate or rewrite text, create images, edit images from references, and create videos.
- Preserve original image ratios by default and organize batch results as connected nodes.
- Record prompts, models, dimensions, quality, and references on generated nodes for retries.

## AI generation

- Connect to user-provided OpenAI-compatible endpoints directly from the browser.
- Configure multiple channels, fetch or enter model names, and choose default text, image, and video models.
- Support image count, aspect ratio, quality, transparent backgrounds, reasoning effort, and custom invocation scripts.
- Support OpenAI-style video endpoints.

## Canvas Agent

- Connect local Codex through Canvas Agent and MCP without giving a web server direct access to browser state.
- Read the active canvas, selection, nodes, edges, generation status, and apply structured operations.
- Use Codex from the browser side panel with streaming responses, history, approvals, permissions, diagnostics, and local Skills.
- Isolate active canvases and turns across multiple browser tabs.

See [Codex App Plugin](/docs/overview/codex-app-plugin) for installation and usage.

## Plugin system

Canvas plugins can contribute node types, rendering, inspectors, serialization, migration, toolbar actions, and optional AI generation capabilities. Built-in and local plugins are managed through the canvas UI.

## Prompts and assets

- Use seven built-in prompt sources from the [Image Prompts](https://github.com/yukkcat/image-prompts) registry, with independent enablement, manual refresh, and scheduled refresh.
- Add, edit, and remove custom standard JSON sources while retaining the last successful cache when refresh fails.
- Search across enabled sources, filter by tags, inspect prompt details, copy prompts, and insert them into the canvas.
- Store reusable images, videos, audio, and prompt assets in the browser.

See [Third-party Prompt Sources](/docs/overview/third-party-prompt-repositories) for the complete built-in list.

## Configuration and synchronization

- Export and import channel, model, generation, prompt-source, and WebDAV settings.
- Store application data and API credentials locally in the browser.
- Use WebDAV for optional cross-device synchronization.

## 3D Director

A 3D scene directing tool based on Three.js / React Three Fiber, supporting multi-character, multi-camera-route productions and final video exports.

### Multi-view Consistency

The main viewport, monitor window, and first-person view play the same timeline in sync; animation poses, camera positions, and panorama backgrounds are consistent across all views, and scrubbing/replay returns to identical poses.

### Camera and Character Routes

- Unified support for smooth/straight route types and constant/gentle/custom segment easing curves.
- Route points can be set to "pass through" or "hold"; holds can specify duration and a hold action (plays from arrival time, resumes next segment after hold ends).
- Dual-rail timeline at the bottom shows both camera and character movement and hold segments simultaneously.
- Custom easing supports straight, slow-start, slow-stop, and gentle-both-ends; characters and camera share the same control and data fields.
- Main viewport, camera rig, and trajectory panels all highlight and jump based on computed arrival times, not legacy trackpoint timestamps.

### Body Part Tracking

- Each camera point can independently select a character and body part: full body, head, chest, waist, limbs — 16 semantic regions.
- Supports instant follow and gentle follow modes; main viewport, monitor window, and exports share the same runtime result.

### External Rigged Character Import

- Supports FBX / GLB character models with built-in skeleton recognition and automatic mapping of 15 semantic bone regions.
- Inspection dialog can supplement unknown skeletons (Bip/UE4, CC Base, etc.); mapping results are used for external animation retargeting and body-part tracking.
- Auto upright, scale to reasonable height, and snap to ground.
- Model library cards show compatibility tags: "Animation Ready", "Needs Skeleton Mapping", "Built-in Animation Only", "Static Only".

### Panorama and Ground

- Supports JPG / PNG / WEBP panorama import; binary stored in IndexedDB, project state keeps only stable references.
- Replace, delete, left/right rotate, brightness adjust, and reset to default direction.
- Five views (main viewport, first-person, monitor window, preview window, export preview) all share the same panorama asset.
- 5 ground materials: studio, concrete, asphalt, wood floor, grass; edit grid, snap-to-grid movement, and ground toggle are independent.

### Community Camera Presets

Built-in presets: dolly in/out, pan left/right, tilt up/down, track shot, arc crane, handheld shake, and parallel tracking. Selectable follow target with real-time trajectory range adjustment.

### Performance Profiles

Three options from the performance menu:
- **Auto**: selects internal profile based on device capability.
- **Smooth**: lower DPR and UI refresh rate for low-end devices.
- **Quality**: highest render fidelity for high-performance devices.

Profiles uniformly control DPR, anti-aliasing, and playback refresh rate for the main viewport, monitor window, and Gizmo; 720p/1080p final video exports are unaffected by edit preview settings.

### Extension Protocol

No built-in ComfyUI or LLM binding — only stable interfaces for third-party development:
- `capabilities.get`: query protocol version, project version, and export capabilities.
- `project.get`: read a deep-copied project snapshot (scene, camera, FOV, camera routes, character routes, animations, per-point tracking targets), without exposing UI state.
- `timeline.get`: read current playback progress, seconds, duration, play state, and active camera.
- `export.frame`: programmatically export first, current, or last frame (720p/1080p PNG).
- `export.video`: programmatically export reference video (720p/1080p, 24/30/60 FPS, WebM Blob).

Project JSON uses an explicit migration pipeline (version `0 → 1`); future versions are explicitly rejected instead of silently dropping fields.

## Current limitations

- The project is frontend-first and does not provide built-in cloud accounts or cloud storage.
- API keys remain in browser storage and requests are sent directly to configured providers.
- Production Docker static-resource paths still require broader deployment verification.
